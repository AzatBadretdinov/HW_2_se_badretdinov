# ПОС — Преподавательская оценка студентов

Домашнее задание № 2 по КПО. Консольное приложение на **Go 1.22+**: учёт студентов,
рубрикатор, выставление/исправление/отмена оценок, взвешенный итог, ведомость,
статистика и экспорт в CSV. Зависимости — только стандартная библиотека Go.

## Запуск

Из корня проекта:

```powershell
go run ./cmd/pos
```

В Windows при необходимости включите UTF-8 в старой консоли: `chcp 65001`.
В Windows Terminal и терминалах современных IDE русские строки обычно отображаются сразу.

```powershell
go build -o bin/pos.exe ./cmd/pos
.\bin\pos.exe
```

Для Linux/macOS: `go build -o bin/pos ./cmd/pos`, затем `./bin/pos`.

По умолчанию данные записываются в `data/course.json` после каждой успешной операции.
Файл и каталог создаются при первом сохранении. При следующем запуске данные восстанавливаются.
Все относительные пути отсчитываются от текущего рабочего каталога.

```powershell
go run ./cmd/pos --data data/my-course.json --export my-results.csv
go run ./cmd/pos --help
```

## Сквозная демонстрация

```powershell
go run ./cmd/pos --demo --export demo-results.csv
```

Демонстрация использует отдельное хранилище `data/demo-course.json`:

1. Создаёт Анну Иванову (`s1`) и Бориса Петрова (`s2`).
2. Добавляет ДЗ (`hw`, максимум 20, вес 40) и экзамен (`exam`, максимум 10, вес 60).
3. Выставляет Анне 16/20 и 9/10, Борису — 10/20 за ДЗ.
4. Показывает отказ при попытке поставить 12 баллов из 10.
5. Показывает отказ строгого режима для студента с пропущенной оценкой.
6. Выводит итоги: **Анна — 8.60, Борис — 2.00**; средний итог — 5.30.
7. Экспортирует ведомость в `demo-results.csv`.

Повторный запуск демонстрации на непустом хранилище отклоняется. Для ещё одного прогона
укажите новый путь: `go run ./cmd/pos --demo --data data/demo2.json --export demo2-results.csv`.
Просмотреть уже созданные данные можно интерактивно:
`go run ./cmd/pos --data data/demo-course.json`.

В `examples/` приложены сохранённые результаты проверенного демонстрационного прогона.
Они не подменяют рабочее хранилище, поэтому первый запуск `--demo` остаётся доступен.

## Команды консоли

| Команда | Действие |
| --- | --- |
| 1, 2 | Добавить студента; посмотреть список |
| 3, 4 | Изменить ФИО; удалить студента вместе с его оценками |
| 5, 6 | Добавить критерий; посмотреть рубрикатор |
| 7, 8 | Изменить название/максимум/вес; удалить критерий без оценок |
| 9 | Выставить оценку или заменить существующую по той же паре студент–критерий |
| 10, 11 | Посмотреть оценки студента, включая пропуски; отменить оценку |
| 12 | Получить итог одного студента |
| 13 | Получить ведомость, средний итог, минимум и максимум |
| 14 | Экспортировать текущие итоги в CSV |
| 15 | Выбрать режим `zero` или `strict` |
| 0 | Завершить работу |

Приложение запрашивает поля по очереди. ID задаются пользователем, чувствительны к регистру
и не меняются при переименовании. Допустимы буквы, цифры, `.`, `_`, `-`; длина — 1–64 символа.
Имя/название — 1–200 символов. Пробелы по краям убираются, управляющие символы в именах запрещены.
Комментарий необязателен, до 1000 символов. EOF завершает ввод; незаконченная команда не сохраняется.
После ошибочного ввода программа объясняет причину и возвращается в меню.

## Правила расчёта и принятые решения

Приняты правила:

```text
итог = 10 × Σ ((балл_i / максимум_i) × вес_i) / Σ вес_i
```

- Итог находится в диапазоне **0–10**. Сначала считается вся формула, затем результат
  округляется до двух знаков обычным математическим округлением (`math.Round`).
- Максимумы и веса строго положительны. Веса относительные: `40/60`, `0.4/0.6` и `2/3`
  дают один результат. Требовать сумму весов 1 или 100 не нужно.
- `zero` — отсутствующая оценка даёт 0, её критерий остаётся в знаменателе.
  Это режим по умолчанию; неполнота явно показана как `оценено N/M`.
- `strict` — итог разрешён только после заполнения всех критериев. Если хотя бы один
  студент не оценён полностью, общая ведомость/экспорт отклоняется целиком.
- Выставленный ноль отличается от отсутствующей оценки и считается заполненным критерием.
- Пустой рубрикатор не даёт осмысленного итога: возвращается понятная ошибка.
- Ввод баллов/весов точный: до двух десятичных знаков, точка или запятая;
  диапазон 0–1 000 000. `NaN`, бесконечность, отрицательные числа, экспоненциальная запись
  и лишние знаки после запятой отклоняются. Ноль допустим для балла, но не максимума/веса.
- Баллы и веса хранятся целым числом сотых. При расчёте отношений используется `float64`;
  внутренние слагаемые не округляются, а итог не сохраняется в хранилище.
- Изменение оценки, веса, максимума или состава рубрикатора сразу влияет на следующий расчёт.
- Нельзя уменьшить максимум ниже любой уже выставленной оценки. Нельзя удалить критерий,
  пока по нему есть оценки: сначала нужно их отменить. Удаление студента удаляет его оценки.
- Режим расчёта выбирается на сеанс, записывается в CSV и при новом запуске снова равен `zero`.

Пример: `10 × ((16/20 × 40) + (9/10 × 60)) / 100 = 8.60`.

CSV: UTF-8 с BOM, разделитель `;`, строки CRLF, заголовок
`student_id;student_name;final_score;assessed;total;policy`. Десятичный разделитель — точка.
Кавычки и разделители в ФИО обрабатывает `encoding/csv`.
Экспорт поверх текущего JSON-хранилища запрещён.

## Карта DDD

Ограниченный контекст — оценивание **одного курса**. Пересдачи, апелляции,
учётные записи преподавателей и несколько курсов не входят в эту модель.

| Понятие предметной области | Код | Роль |
| --- | --- | --- |
| Студент | `domain.Student` | Entity со стабильным `ID`, ФИО можно менять |
| Критерий | `domain.Criterion` | Entity со стабильным `ID`, максимумом и относительным весом |
| Оценка | `domain.Evaluation` | Entity с составной идентичностью `(StudentID, CriterionID)`; исправление сохраняет эту пару |
| Курс с рубрикатором и оценками | `domain.Course` | Корень агрегата, единственная точка изменения состояния |
| Идентификатор, балл, вес | `domain.ID`, `Score`, `Weight` | Value Objects: собственная идентичность отсутствует, сравнение по значению |
| Итог | `domain.FinalScoreService` | Domain Service: связывает студента, текущий рубрикатор и оценки |
| Хранилище курса | `domain.CourseRepository` | Порт репозитория, реализация находится снаружи домена |

Пример Entity/VO: переименование `s1` не создаёт нового студента, его оценки остаются связанными
с `s1`. Два значения `Score("7.50")` равны по содержимому; заменив одно другим, мы не изменяем
личность какого-либо объекта.

### Граница агрегата и инварианты

`Course` объединяет студентов, рубрикатор и оценки: проверку наличия критерия и диапазона балла
можно выполнить в одной границе согласованности. Для учебного модуля одного небольшого курса
это проще нескольких репозиториев с межагрегатными транзакциями.

Поля сущностей и коллекции закрыты. Методы чтения возвращают значения/новые срезы;
через полученный список нельзя изменить исходные данные. Изменения выполняются только методами
корня агрегата (`AddStudent`, `UpdateCriterion`, `SetEvaluation` и т. д.).
Создавайте агрегат через `domain.NewCourse()`.

`EvaluationFactory.Create` проверяет существование студента, принадлежность критерия рубрикатору,
диапазон балла и комментарий. `SetEvaluation` вставляет результат только после успешных проверок.
Публичного способа вставить произвольную готовую `Evaluation` в агрегат нет.
При загрузке JSON те же операции повторяются: файл не может обойти доменные правила.

Таким образом, домен содержит поведение и охраняет инварианты. DTO используются только
на границах, а не вместо доменных сущностей.

## Архитектура: Ports and Adapters

```text
cmd/pos                     composition root, флаги, регистрация зависимостей
internal/adapters/console    входящий адаптер: меню и демонстрация
internal/adapters/storage    исходящий адаптер: JSONRepository + DTO
internal/adapters/export     исходящий адаптер: CSVExporter
internal/adapters/files      общая файловая операция для двух исходящих адаптеров
internal/application         Facade, сценарии, DTO для UI, порт ResultsExporter
internal/domain              агрегат, сущности, VO, builder, фабрика, стратегии, domain service,
                             порт CourseRepository
internal/di                  DI-контейнер, используется только при сборке графа
```

Направление **зависимостей исходного кода**:

```text
console ────────────> application ────────────> domain
export ─────────────> application
storage ─────────────────────────────────────> domain
cmd/pos ────────────> адаптеры + application + domain + di
```

`Domain` использует только стандартную библиотеку, без консоли, файлов, CSV/JSON и DI.
`Application` зависит только от домена и абстракции экспорта. `JSONRepository` реализует
доменный порт; `CSVExporter` — порт приложения. Консоль вызывает фасад и не обращается
к файловому хранилищу напрямую.

Поток выполнения отличается от направления зависимостей: UI вызывает сценарий,
сценарий вызывает интерфейс репозитория, а фактическое выполнение переходит в адаптер.
Это инверсия зависимостей, описанная в лекции 8.

### DI-контейнер

`internal/di` — небольшой реальный контейнер: типизированная регистрация провайдеров,
ленивое разрешение зависимостей, singleton-кеш и обнаружение циклов/отсутствующих регистраций.
Использованы generics и `reflect.Type` стандартной библиотеки, внешние пакеты не нужны.

`cmd/pos.compose` регистрирует репозиторий, экспортёр, domain service, набор стратегий,
фасад и UI. При запросе UI контейнер разрешает весь граф. Конструкторы получают готовые
зависимости; контейнер не передаётся в бизнес-код, то есть Service Locator не используется.
Контейнер рассчитан на однопоточное приложение и не используется после сборки графа.

## Паттерны

Использован классический GoF-паттерн из каждой требуемой группы:

| Группа | Паттерн и место | Какую задачу решает |
| --- | --- | --- |
| Порождающие | **Builder**, `domain.CourseBuilder`, используется в `storage.decode` | Собирает сложный агрегат из наборов записей: шаги можно задавать в любом порядке, ссылки разрешаются при `Build`, частичный результат наружу не попадает |
| Структурные | **Facade**, `application.Facade` | Консоль вызывает готовый сценарий, а не собирает последовательность Load → изменение домена → Save и расчёт → экспорт |
| Поведенческие | **Strategy**, `domain.ScoreStrategy`, `WeightedZero`, `WeightedComplete` | Меняет политику неполных оценок без изменения UI и основного алгоритма domain service |

Дополнительно используется простая фабрика `EvaluationFactory`, непосредственно предложенная
в условии для создания `Evaluation`. Она не выдаётся за классический Factory Method;
порождающую группу закрывает именно Builder. Фабрика централизует проверку контекста
оценки и не требует искусственной иерархии типов оценок. Итого в порождающей группе не более
двух решений, в остальных — по одному. Название «адаптер» в структуре
проекта обозначает архитектурную роль реализации порта, а не дополнительный GoF-паттерн
с несовместимым сторонним интерфейсом.

## Сохранение и ошибки

JSON имеет версию схемы `1`, содержит только студентов, критерии и оценки.
Максимумы, баллы и веса записаны строками с двумя знаками после точки.
Порядок записей стабилен по ID. После загрузки проверяются версия, неизвестные поля,
дубликаты ID/оценок, ссылки и остальные доменные ограничения.
JSON-адаптер выступает директором для `CourseBuilder`: передаёт шаги из DTO, а строитель
создаёт продукт, применяя операции агрегата. Сам строитель не знает о JSON или файлах.

Сохранение/экспорт: создание временного файла рядом с целевым → полная запись → `Sync` →
закрытие → переименование. Ошибка проверки или записи не приводит к сохранению неполного
нового документа. Гарантии атомарности переименования зависят от ОС/файловой системы.
Повреждённый исходный JSON не перезаписывается; приложение сообщает причину.

В памяти приложения нет долговременного изменяемого кеша курса: каждый сценарий загружает
снимок, применяет доменное действие и сохраняет результат. Приложение предназначено
для одного процесса; блокировки между несколькими одновременно запущенными экземплярами
и миграции между версиями схемы не реализованы.

## Проверка

```powershell
go test ./...
go vet ./...
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

При наличии C-компилятора и включённом CGO можно дополнительно выполнить `go test -race ./...`.

Проверяются не только успешные операции:

- точный десятичный ввод и отказ от отрицательных/нечисловых/слишком точных баллов;
- границы `[0, max]`, неизвестные студент/критерий, сохранность прежней оценки при отказе;
- взвешенный итог, пропуски, строгая стратегия, исправление и отмена оценки;
- пересчёт после изменения весов и добавления нового критерия;
- невозможность уменьшить максимум ниже имеющейся оценки/удалить используемый критерий;
- идентичность студента, закрытость коллекций, каскадное удаление оценок;
- сквозной ввод в меню, реальные JSON и CSV, восстановление после нового запуска;
- русские ФИО с кавычками/разделителем в CSV, защита хранилища от экспорта поверх него;
- отказ от повреждённого JSON и повторного demo без изменения исходного файла;
- Builder: разрешение ссылок независимо от порядка шагов, независимость продуктов и отказ от частичного результата;
- EOF в середине команды, неизвестная команда и DI: singleton, отсутствующая регистрация, цикл.

## Роль ИИ

ИИ использовался для подбора тестовых сценариев, написания тестов на доменные инварианты и расчёт итогового балла, а также анализа результатов тестирования. Архитектура и основной код приложения разработаны самостоятельно.
